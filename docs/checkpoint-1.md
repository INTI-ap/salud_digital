## 1. Lista de verificación

| N.º | Criterio | Estado | Evidencia |
|---|---|---|---|
| 01 | La app compila y se ejecuta en un emulador o dispositivo con servicios de Google Play. | ☐ | Captura y hash del commit |
| 02 | El paquete (`applicationId`) coincide con el registrado en Firebase. | ☐ | Valor y captura de la consola |
| 03 | `flutterfire configure` se ejecutó y los archivos de configuración están en el proyecto. | ☐ | `android/app/google-services.json` |
| 04 | `Firebase.initializeApp` se ejecuta antes de `runApp` y la consola imprime el proyecto. | ☐ | Salida de `flutter run` |
| 05 | La entidad de dominio no depende de Flutter. | ☐ | Revisión de `domain/` |
| 06 | Existe un contrato de repositorio y una implementación en memoria. | ☐ | Revisión de `data/` |
| 07 | El bloque recibe el repositorio por constructor y no lo instancia. | ☐ | Revisión de `bloc/` |
| 08 | Los estados cubren carga, éxito y error. | ☐ | Revisión de `*_state.dart` |
| 09 | La pantalla usa `BlocBuilder` y no contiene reglas de negocio. | ☐ | Revisión de `pages/` |
| 10 | Los botones tienen texto o etiqueta semántica; el texto se lee con escalado 1.5×. | ☐ | Prueba con TalkBack y escalado |
| 11 | El repositorio tiene README, ADR, `.gitignore` y commits descriptivos. | ☐ | Enlace al repositorio |
| 12 | El tablero está actualizado y cada tarea tiene responsable. | ☐ | Enlace al tablero |
